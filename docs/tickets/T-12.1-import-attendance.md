# T-12.1 – Import attendance from Excel

**Goal:** when the system is down, workers sign a printed or shared Excel sheet instead of clocking in; afterwards the Admin downloads the system's template, fills it (or copies the sheet into it), uploads it on All Attendance → "Import Attendance", and every valid row becomes a costed attendance on its project. Bad rows are listed so the Admin can fix and re-upload only those.

**Depends on:** T-12 (corrections, per-save password), T-11.3 (counting within the shift), T-03 (rate history)

**Current implementation**

- All Attendance (`/attendance`, `App\Livewire\Attendance\Index`, permission `attendance.view-all`) has two tabs, `daily` and `employee` (`Index::TABS`, `#[Url(as: 'tab')]`), drawn as buttons in `resources/views/livewire/attendance/index.blade.php`; each tab is a partial in `resources/views/livewire/attendance/partials/`.
- `AttendanceService::clockIn()` saves the hourly rate and the shift windows at clock-in (including a night shift started the day before); `clockOut()` computes `clocked_minutes`, `minutes_worked` (`ShiftMinutes::counted()`), `hours_worked` and `labor_cost` (`LaborCost::forMinutes()`).
- `user_rate_histories` (`user_id`, `hourly_rate`, `effective_from`) holds every rate change (T-03).
- `App\Livewire\Attendance\Correction` (T-12) checks the Admin's password on every save with a five-per-minute limit (`confirmPassword()`).
- `maatwebsite/excel` is installed (named in CLAUDE.md); no export or import classes exist yet (T-18 adds the reports).
- Attendance uses soft deletes; a correction archives the original and creates new rows (`corrected_from_id`).

**Build**

- Migration (new file) `create_attendance_imports_table`: `id`, `file_name` string(255), `imported_by` (FK users), `rows_total`, `rows_imported`, `rows_failed` (unsigned int), `failures` JSON (list of `{row, employee_no, reason}`), timestamps. Model `App\Models\AttendanceImport` (`failures` cast to array; `importedBy()` belongs-to, with trashed).
- Migration (new file) `add_attendance_import_id_to_attendances_table`: `attendance_import_id` nullable FK to `attendance_imports`, `nullOnDelete`. `Attendance::import()` belongs-to.
- Refactor, no behavior change: move the shift-window building in `AttendanceService::clockIn()` (today's windows plus a night shift from the day before) into a public `AttendanceService::shiftWindowsAt(User $user, CarbonInterface $clockIn): ?array` returning the saved `[{start, end}]` format; `clockIn()` and the import both use it.
- `App\Services\UserRateService::rateOn(User $user, CarbonInterface $date): string` — the `hourly_rate` of the latest `user_rate_histories` row with `effective_from` ≤ the date; the user's current `hourly_rate` when there is none.
- Template: `App\Exports\AttendanceImportTemplateExport` (`WithMultipleSheets`), file name `attendance-import-template.xlsx`:
  - Sheet "Attendance": header row `Employee No.`, `Employee Name`, `Project Code`, `Date`, `Clock In`, `Clock Out`, then two example rows in gray italics that say "(example, delete this row)" in Employee Name; `Date`, `Clock In` and `Clock Out` columns formatted as text (`@`) so Excel keeps what is typed.
  - Sheet "Employees": `Employee No.`, `Name`, `Shift` for every active user with `attendance.clock`, by last name.
  - Sheet "Projects": `Code`, `Name`, `Location` for every Ongoing project, by code.
  - Sheet "Instructions": one rule per line: date as `2026-10-21`; times as `7:00 AM` or `07:00` (24-hour); a clock-out earlier than the clock-in means the next day (overnight); one row per clock-in/clock-out; Employee Name is only for reading and is not checked; example rows are skipped.
- Reading: `App\Imports\AttendanceSheetImport` (`ToCollection`, `WithHeadingRow`, first sheet only) only reads rows; all checks are in the service.
- `App\Services\AttendanceImportService::import(string $path, string $fileName, User $admin): AttendanceImport` — reads the "Attendance" sheet, skips blank rows and the example rows, checks each row and saves the valid ones, each in its own transaction that locks the user row (like clock-in). Row numbers in failures are the spreadsheet row (header = row 1). Per row:
  - `Employee No.` matches a user who is not archived and has `attendance.clock`; otherwise "Unknown employee no." Inactive users are allowed (the sheet may be from before they left).
  - `Project Code` matches a project that is not archived and is Ongoing (the clock-in rule, PRD US-10); otherwise "Unknown project code" or "Project is not Ongoing".
  - `Date` parses as `Y-m-d` (also an Excel date serial); `Clock In` / `Clock Out` parse as `g:i A`, `h:i A`, `H:i` (also an Excel time fraction). Otherwise "Invalid date" / "Invalid clock-in time" / "Invalid clock-out time". A clock-out earlier than the clock-in is the next day; equal times fail with "Clock-out must be after clock-in".
  - Not in the future (now, Asia/Manila): "Times cannot be in the future".
  - No overlap with the same user's attendance that is not void (archived records never count) or with an earlier valid row of the same file: "Overlaps another attendance of this employee (7:00 AM–11:30 AM)".
  - A saved row: `work_date` = the date, `clock_in_at` / `clock_out_at`, `hourly_rate` = `UserRateService::rateOn()` for the date, `shift_windows` = `shiftWindowsAt()` at the clock-in, minutes / hours / labor cost exactly as `clockOut()` computes them, `status = closed`, `attendance_import_id` set; no location or photo.
  - The `AttendanceImport` row is saved with the counts and failures, and returned.
- Livewire `App\Livewire\Attendance\Import` (view `resources/views/livewire/attendance/import.blade.php`, `WithFileUploads`, `WithPerPage`), embedded as the third tab `import` ("Import Attendance", icon `arrow-up-tray`) on All Attendance. The tab button and its content show only with `attendance.correct` (Admin); `Index::mount()`/`updated()` fall back to `daily` for anyone else. `boot()` checks `attendance.correct` on every request.
  - Card 1, "Download the template": a short line and a "Download template" button (`downloadTemplate()`, returns the Excel download).
  - Card 2, "Upload the filled-in file": `flux:input type="file"` (`.xlsx`, `.xls`, `.csv`; max 2 MB; at most 1,000 data rows, more fails with "The file has more than 1,000 rows. Split it and upload each part."), the Admin's password (same `confirmPassword()` as corrections: `current_password`, five wrong passwords per minute lock it; extract it from `Correction` into `App\Livewire\Concerns\ConfirmsPassword` and use it in both), and an "Import" button (`btn-accent`). The password is cleared after every attempt.
  - Result (after an import): `<x-stat-card>`s "Rows read", "Imported" (green), "Not imported" (red); when some rows failed, a table Row / Employee No. / Reason (paginated with `WithPerPage` and `<x-table-footer>`, stacked cards on phones) and the note "Fix these rows in the file, delete the rows that were imported, and upload it again."
  - "Recent imports": `attendance_imports` newest first — date and time, file name, imported by (`<x-avatar>`), imported / not imported counts; paginated; a row menu item "Show rows not imported" fills the result table from that import's `failures`.
  - Toast after import: "12 attendance records imported. 3 rows were not imported."
- Attendance tables: an imported record shows a small `<x-status-badge color="info">Imported</x-status-badge>` in the Remarks cell (`day-remarks` partial) and the phone card; screen wording stays "attendance" (never "session" or "duty").
- Imported records can be corrected like any other (T-12).

**Acceptance criteria**

- [ ] Admin opens All Attendance → Import Attendance, downloads the template, and it has the Attendance, Employees, Projects and Instructions sheets.
- [ ] Uploading a filled template with the correct password creates one Clocked Out attendance per valid row, on the right project, with the rate effective on that date and the hours counted within the user's shift; each project's labor total grows by exactly the imported labor cost.
- [ ] Rows with problems are not saved and are listed with their row number and reason; the valid rows of the same file are saved.
- [ ] A missing or wrong password imports nothing; five wrong passwords in a minute lock importing for that minute.
- [ ] Staff and Workers do not see the tab and get 403 on `downloadTemplate()` and `import()`.

**Tests**

- Unit: `UserRateService::rateOn()` — rate ₱80.00 effective 2026-10-01 and ₱95.00 effective 2026-10-20: 2026-10-19 → `80.00`, 2026-10-20 → `95.00`, 2026-09-30 → the user's current rate.
- Feature: `Excel::fake()`; `downloadTemplate()` downloads `attendance-import-template.xlsx` (Admin); Staff gets 403.
- Feature (files built in the test with a `FromArray` export stored to a fake disk), today 2026-10-21 18:00 Asia/Manila:
  - Flexible worker at ₱80.00: 2026-10-19 7:00 AM–11:30 AM and 12:30 PM–5:00 PM → two records of 270 minutes, 4.50 h, ₱360.00 each, `status = closed`, `attendance_import_id` set; the project's `laborTotal()` goes from 0.00 to 720.00.
  - Rate change: the same worker with ₱95.00 effective 2026-10-20, row on 2026-10-20 7:00–11:30 → ₱427.50.
  - Overnight: 2026-10-19 22:00 → 06:00 at ₱95.50 → 480 minutes, 8.00 h, ₱764.00, work date 2026-10-19 (PRD 10.2).
  - Shift: two shifts 8:00–12:00 and 13:00–17:00, row 7:50 AM–12:24 PM → 240 minutes, 4.00 h, ₱320.00 (T-11.3).
  - Mixed file: 3 good rows + unknown employee no., unknown project code, clock-out equal to clock-in, a future date, overlap with an existing attendance, overlap with an earlier row of the file → 3 saved, 6 listed with the right row numbers and reasons; `rows_total = 9`, `rows_imported = 3`, `rows_failed = 6`.
  - Example rows and blank rows are skipped and not counted.
  - A missing and a wrong password (`#[DataProvider]`): nothing saved, error on `password`.
  - Staff and Worker: `Livewire::test(Import::class)` is forbidden; the Import tab button is not rendered for Staff.
